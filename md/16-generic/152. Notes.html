Section 16: Generics



Lecture 1: Generic Classes


Introduction

Generics are one of the most powerful and important features of the C# language. They allow you to design classes, interfaces, and methods with a placeholder for a data type (T). This placeholder is specified later by the developer who uses your code, allowing them to create type-safe and high-performance data structures without sacrificing reusability.


To understand why generics are so crucial, we must look at the problem they solved. Before generics, the only way to create a reusable collection was to use System.Object. For example, the old ArrayList stored everything as an object. This caused two major problems:

  1. Lack of Type Safety: You could add any type of data to an ArrayList. You could add an integer, then a string, then a Car object. When you later retrieved an item, you had to perform an explicit cast and hope it was the correct type. This often led to InvalidCastException errors at run-time.

  2. Poor Performance (Boxing): When you added a value type (like an int or double) to an ArrayList, it had to be boxed (wrapped in an object on the heap). When you retrieved it, it had to be unboxed. As we learned, these operations are computationally expensive and create pressure on the garbage collector.

Generics solve both of these problems elegantly.


How It Works: Type Parameters and JIT Specialization

You create a generic class by adding a type parameter in angle brackets after the class name. The letter T is a conventional placeholder for "Type".

Syntax: public class MyList<T> { ... }

When a developer uses your generic class, they specify a concrete type, creating what is called a closed generic type: MyList<int> or MyList<string>.

The .NET Just-In-Time (JIT) compiler then performs a specialization process:

  • For value types (like int, double, struct), the JIT compiler creates a brand new, highly optimized version of the class specifically for that value type. MyList<int> becomes a class where T is replaced with int everywhere, completely avoiding any boxing or unboxing.

  • For reference types (string, Car, etc.), the JIT is able to reuse a single underlying implementation for all of them, because all references are the same size.


Example: A Reusable Repository

Let's create a simple generic Repository<T> class that can store and retrieve any type of data entity.

C#

// 'T' is a placeholder for whatever type we want this repository to handle.
public class Repository<T>
{
    private List<T> _items = new List<T>();

    public void Add(T item)
    {
        _items.Add(item);
    }

    public T GetById(int index)
    {
        return _items[index];
    }
}

public class Employee { public string Name { get; set; } }
public class Product { public string Sku { get; set; } }

// --- In your Main method ---
// 1. Create a repository specifically for Employee objects.
Repository<Employee> employeeRepo = new Repository<Employee>();
employeeRepo.Add(new Employee { Name = "John Doe" });
// employeeRepo.Add(new Product()); // ERROR! Compiler enforces type safety.

// 2. Create another repository specifically for Product objects.
Repository<Product> productRepo = new Repository<Product>();
productRepo.Add(new Product { Sku = "XYZ-123" });

// We have achieved both type safety and code reusability.



Lecture 2: Multiple Generic Parameters


Introduction

A generic class or method is not limited to a single type parameter. You can define multiple placeholders for different types when your class needs to work with a combination of them.


How It Works: Comma-Separated Type Parameters

You declare multiple type parameters by listing them inside the angle brackets, separated by commas. By convention, the letters T, U, V are often used, or more descriptive names like TKey and TValue.

Syntax: public class MyClass<T, U> { ... }


Why and When to Use It

Use multiple generic parameters when you are creating a class that naturally pairs or relates two or more different and potentially unrelated types. The most famous example in the .NET framework is Dictionary<TKey, TValue>, which needs one generic type for its keys and another for its values.


Example: A Simple Pair Class

Let's create a generic Pair class that can hold any two items together.

C#

// This class uses two type parameters, TFirst and TSecond.
public class Pair<TFirst, TSecond>
{
    public TFirst First { get; set; }
    public TSecond Second { get; set; }

    public Pair(TFirst first, TSecond second)
    {
        this.First = first;
        this.Second = second;
    }
}

// --- In your Main method ---
// Create a pair of a string and an integer.
Pair<string, int> nameAndAge = new Pair<string, int>("Alice", 30);
Console.WriteLine($"Name: {nameAndAge.First}, Age: {nameAndAge.Second}");

// Create a pair of an Employee object and a double.
Employee emp = new Employee { Name = "Bob" };
Pair<Employee, double> employeeAndSalary = new Pair<Employee, double>(emp, 75000.50);
Console.WriteLine($"Employee: {employeeAndSalary.First.Name}, Salary: {employeeAndSalary.Second}");



Lecture 3: Generic Constraints


Introduction

Constraints are rules that you apply to a generic type parameter to restrict the types that can be used with your generic class or method. Without constraints, the compiler's only assumption about a type parameter T is that it derives from System.Object. This means you can only call methods on T that are defined in System.Object (like ToString(), Equals(), etc.).

Constraints give the compiler more information about the capabilities of T, allowing you to call specific methods or access specific properties on it.


How It Works: The where Clause

You apply constraints using the where keyword after the generic type parameter list.

Syntax: public class MyClass<T> where T : ...


Common Types of Constraints

  • where T : class: The type argument must be a reference type (a class, interface, delegate, or array).

  • where T : struct: The type argument must be a non-nullable value type (an int, double, bool, or a custom struct).

  • where T : new(): The type argument must have a public, parameterless constructor. This allows you to create new instances of T within your generic class (new T()). This constraint must be the last one in the list.

  • where T : <base class name>: The type argument must be, or derive from, the specified base class. This allows you to safely use all the public members of that base class on T.

  • where T : <interface name>: The type argument must implement the specified interface. This is one of the most common and powerful constraints, as it allows you to call the interface's methods on T.


Example: Constraining to an Interface

Let's create a generic reporting service that can generate a report from any object, as long as that object has a Name property. We can enforce this with an interface.

C#

// 1. Define the contract (the interface).
public interface IEntityWithName
{
    string Name { get; }
}

// 2. Create some classes that implement the interface.
public class Product : IEntityWithName
{
    public string Name { get; set; }
    public decimal Price { get; set; }
}
public class Customer : IEntityWithName
{
    public string Name { get; set; }
    public int Id { get; set; }
}

// 3. Create the generic class with a constraint.
public class ReportGenerator<T> where T : IEntityWithName
{
    public void GenerateReport(T item)
    {
        // Because of the constraint, the compiler KNOWS that 'item'
        // will have a 'Name' property, so this code is safe.
        Console.WriteLine($"--- Report for {item.Name} ---");
        // ... more reporting logic ...
    }
}

// --- In your Main method ---
var generator = new ReportGenerator<Product>();
generator.GenerateReport(new Product { Name = "Laptop", Price = 1200 });

// This would cause a compiler error because 'int' does not implement IEntityWithName.
// var intGenerator = new ReportGenerator<int>(); // ERROR!



Lecture 4: Generic Methods


Introduction

A generic method is a method that is declared with its own type parameters. This allows a single method to perform the same action on a wide variety of different data types while still maintaining full type safety. A key feature is that a generic method can exist inside a non-generic class.


How It Works: Syntax and Type Inference

You declare a generic method by placing the type parameter in angle brackets immediately after the method name.

Syntax: access_modifier return_type MethodName<T>(T parameter) { ... }

One of the most powerful features of generic methods is type inference. In most cases, the C# compiler is smart enough to deduce the type T from the arguments you pass to the method. This means you usually don't have to explicitly specify the type in angle brackets when you call the method.


Why and When to Use It

Use a generic method when you need a single, standalone utility function that performs an action that is not dependent on a specific data type. This is perfect for general-purpose operations like swapping, sorting, or comparing items. The classic textbook example is a Swap method.


Example: A Reusable Swap Method

Without generics, you would need to write a separate Swap method for integers, one for strings, one for doubles, and so on. With a generic method, you only need to write it once.

C#

public class Utilities
{
    // This is a generic method. 'T' can be any type.
    public static void Swap<T>(ref T a, ref T b)
    {
        Console.WriteLine($"Swapping items of type: {typeof(T).Name}");
        T temp = a;
        a = b;
        b = temp;
    }
}

// --- In your Main method ---
// --- Swapping Integers ---
int x = 5;
int y = 10;
Console.WriteLine($"Before: x={x}, y={y}");
// We call Swap, not Swap<int>. The compiler infers that T is int.
Utilities.Swap(ref x, ref y);
Console.WriteLine($"After: x={x}, y={y}");

Console.WriteLine("--------------------");

// --- Swapping Strings ---
string s1 = "Hello";
string s2 = "World";
Console.WriteLine($"Before: s1={s1}, s2={s2}");
// Here, the compiler infers that T is string.
Utilities.Swap(ref s1, ref s2);
Console.WriteLine($"After: s1={s1}, s2={s2}");

Output:

Before: x=5, y=10
Swapping items of type: Int32
After: x=10, y=5
--------------------
Before: s1=Hello, s2=World
Swapping items of type: String
After: s1=World, s2=Hello



Lecture 5: IMP Points to Remember


Introduction

This lecture consolidates the most critical, practical, and interview-worthy points about generics. Understanding these concepts demonstrates a professional-level grasp of C#.


1. Generics Solve Two Main Problems

This is the most important takeaway and the ideal answer to the interview question, "Why does C# have generics?"

  • 1. Type Safety: Generics move type checking from run-time to compile-time. When you use List<string>, the compiler guarantees that only strings can be added, preventing InvalidCastException errors that were common with older, non-generic collections.

  • 2. Performance: Generics eliminate the need for boxing and unboxing when working with value types (int, double, struct, etc.). List<int> stores integers directly, whereas the old ArrayList had to "box" each integer into an object on the heap, causing significant performance degradation and pressure on the garbage collector.


2. List<T> vs. ArrayList: The Classic Example

This comparison is the quintessential way to explain the benefits of generics.

  • ArrayList (Old, Non-Generic):

    • Stores everything as object.

    • Not Type-Safe: You can add an int and a string to the same list by mistake.

    • Requires Casting: You must explicitly cast items back to their original type when you retrieve them, risking a run-time error.

    • Causes Boxing: Incurs a performance penalty for value types.

  • List<T> (Modern, Generic):

    • Stores a specific type T.

    • Type-Safe: The compiler enforces that only items of type T can be added.

    • No Casting Needed: When you retrieve an item, it is already of type T.

    • High Performance: No boxing occurs for value types.

You should always use List<T> and other generic collections (Dictionary<TKey, TValue>, Queue<T>, etc.) in modern C# code.


3. Constraints Unlock Functionality

Remember that you use constraints (where T : ...) on a generic type parameter when your method needs to do more than just store or pass around the data. You use constraints when you need to call methods or access properties on the generic type. The most common constraints are:

  • where T : IMyInterface: Lets you call methods defined in IMyInterface.

  • where T : MyBaseClass: Lets you use members from MyBaseClass.

  • where T : new(): Lets you create a new instance of the type using new T().


4. Generic Methods vs. Generic Classes

Use this guideline to decide which to create:

  • Generic Class: Use when the entire class is designed to work as a container or manager for a specific placeholder type. The state of the class (its fields and properties) depends on T. Examples: List<T>, Repository<T>.

  • Generic Method: Use for a single, standalone utility function that performs an action on any type, where the class containing the method does not itself need to be generic. Example: Swap<T>(), Sort<T>().


5. Open vs. Closed Generic Types (Advanced Interview Point)

Knowing this terminology demonstrates a deeper level of understanding.

  • Open Generic Type: The type definition with the placeholder still present. You cannot create an instance of an open type. Example: typeof(List<>).

  • Closed Generic Type: A type where a specific type argument has been provided for the placeholder. This is the type you can instantiate. Example: typeof(List<int>).
